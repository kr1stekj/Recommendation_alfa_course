# Перенос готовых эмбеддингов

Задача: друзья и жюри используют рассчитанные локально векторы без повторной
нейросетевой индексации. После проверки — push и слияние через PR в main.

## Переносимый набор

В Git хранятся precomputed/bge-m3/{encoder.json,vectors.npy,topic_vectors.npy,manifest.json}.
Около4.5МиБ; без catalog.json, пользовательской истории/UUID, дампа, .env и весов
модели. Manifest версии1 содержит SHA256 исходного backup, дату as_of, контрольные
суммы файлов/каталога/тем, ожидаемые формы матриц и исходный fingerprint индекса.
Предположения о темах без исходной метки представлены только индексом темы и двумя
числами на позицию строки: без текста/ID материалов. encoder разрешает только
публичные настройки поддерживаемой semantic-модели с закреплённой revision.

Export читает активное поколение и backup, проверяет, что каталог/история/порядок
совпадают. Нейросеть не вызывается. Существующий output не перезаписывается.
Restore проверяет hashes, формы/dtype/конечность/нормы векторов, модель и контекст,
восстанавливает каталог и историю из локального backup с сохранённой датой as_of,
восстанавливает только числовые аннотации тем, сверяет исходный fingerprint.
При любом несовпадении — явная ошибка до импорта/публикации, без скрытой индексации.

Новое поколение публикуется атомарным переключением current только после импорта
истории в PostgreSQL и проверки файлов. Старое поколение/профили не удаляются.
Каталог/история остаются в локальных ignored-артефактах/БД; схема БД не меняется.

## Запуск

Docker по умолчанию USE_PRECOMPUTED_EMBEDDINGS=1: при пустом томе восстанавливает
индекс из bundle и пользовательского /data/alfa_course_hackathon.backup. Backend
tfidf остаётся явным альтернативным режимом. USE_PRECOMPUTED_EMBEDDINGS=0 включает
прежнюю полную сборку. При semantic и включённом reuse отсутствующий/повреждённый
bundle или несовместимые настройки не приводят к тихому пересчёту.
Существующий действительный индекс по-прежнему переиспользуется.

Перед API отдельно проверяется кеш нужной model/revision и при необходимости
скачиваются только файлы tokenizer/config/весов из публичной модели. Векторизация
каталога и загрузка модели в память для этой подготовки не выполняются. Полностью
готовый кеш не требует сети. Веса≈2.2ГиБ не коммитятся, хранятся в Docker Linux-томе.
На offline-машине нужен заранее заполненный кеш. HF token/LLM API не используются.

Нативный путь: python -m reco.precomputed restore, затем python -m reco.model_cache
и обычный сервер. Export/restore CLI принимают --backup/--artifacts/--bundle по
сценарию. Сам bundle работает одинаково на CPU/MPS; устройство не меняет пространство
векторов. Для NTFS не нужны symlink на хосте: Docker публикует current в Linux-томе.
.gitattributes фиксирует бинарные матрицы и LF для JSON, чтобы hashes не менялись.

## Проверки

Изолированные fixtures: reuse без Encoder.fit/encode, отсутствующий/иной backup,
hashes/config/размеры/NaN/порядок/аннотации, ошибка PostgreSQL/публикации сохраняет
старый индекс. Startup: reuse/default/opt-out/старый индекс/модельный кеш.
Настоящий export/restore сверяет fingerprint и byte-level hashes с активным индексом
на отдельной тестовой БД. Ни реальных LLM-вызовов, ни полной повторной индексации.
Windows/Docker runtime проверяются только при доступности среды, без выдуманных запусков.
