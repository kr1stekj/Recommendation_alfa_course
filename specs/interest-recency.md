# Свежесть интересов

Цель: недавние положительные взаимодействия сильнее старых при сохранении
нескольких тем в персональной ленте. Текущий текстовый запрос сохраняет приоритет
над историей; LLM, индекс, схема БД и TTL не меняются.

1. Live-сигнал материала: исходный вес × 2^(-возраст / 24 часа). Возраст
   ограничен снизу нулём. Отрицательные сигналы затухают как раньше за 7 дней.
   История из дампа остаётся долгосрочной: её актуальные даты неизвестны.
2. Для каждой темы берётся время последнего положительного live-взаимодействия.
   Равные времена имеют равный приоритет. Различные времена сортируются от новых
   к старым; rank=0 для самого нового. Исторические темы без live-даты следуют
   после всех датированных групп.
3. Приоритет темы в стартовой ленте:
   sqrt(сумма положительных затухших весов) / (1 + rank).
   Корень ограничивает влияние большого числа старых кликов. При отсутствии
   live-дат recency-множитель равен 1 для всех тем.
4. До четырёх тем с максимальным приоритетом получают по одному месту, если есть
   подходящие карточки и места. Остальные персональные места выдаются по
   приоритету / (число уже выделенных теме мест + 1). Внутри темы действует
   прежнее ранжирование; одна карточка занимает одно место даже с несколькими
   метками. Популярный слот и знакомство сохраняются (обычно 8/1/1).
5. Повторный настоящий клик обновляет время материала, дубликат event_id - нет.
   Поиск сам по себе не записывает интерес. Нулевые/отрицательные сигналы не
   создают положительный recency-приоритет.

Приёмка: более свежая из двух сопоставимых тем получает больше мест и идёт первой;
смена последнего интереса меняет приоритет; вторая тема остаётся представлена;
за сутки положительный вес уменьшается вдвое; нет дублей, completed/disliked,
LLM-вызовов или пересчёта embeddings. Пустой поиск учитывает это в обоих режимах.
Обратная совместимость: прежние агрегаты уже содержат at, миграция не нужна.
Откат к предыдущему коду возвращает прежний способ подсчёта без потери данных.
