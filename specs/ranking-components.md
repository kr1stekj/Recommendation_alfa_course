# Нормализованные компоненты ранжирования

Задача: сделать вклад каждого сигнала ограниченным и наблюдаемым. Исходная
версия — 7d8e6a9; изменение не требует миграции PostgreSQL или пересборки индекса.

## Формула hybrid-v2

```text
cosine_positive = clip(raw_cosine, 0, 1)
score = 0.75 * cosine_positive
      + 0.16 * topic_match
      + 0.04 * format_match
      + 0.05 * popularity
      - 0.12 * dislike_similarity
      + 0.03 * continuation
```

Все шесть признаков конечны и лежат в [0, 1]. Продолжение — 0/1, активно только
при include_continuations и незавершённом положительном взаимодействии. Сумма
четырёх основных положительных весов равна 1. Итоговый score может быть отрицательным
или превышать 1 из-за штрафа и бонуса продолжения; вероятностью он не является.

raw_cosine в ответе cosine и алгоритм cosine сохраняют математическую шкалу
[-1, 1]. Она используется и для прежних порогов слабого совпадения/отбора пула.
TF-IDF неотрицателен; его косинус не сдвигается. Диапазон ограничивается в признаке
гибрида; ноль не превращается в 0.5.

topic_match — доля выбранных тем, совпавших с канонизированными метками материала.
Это не cosine и не близость к центроидам. Векторные topic_recommendations — отдельный
выход и в topic_match не подставляются. Корреляция тем с семантикой возможна;
она не доказывает необходимость или оптимальность веса 0.16.

## Пропуски

- Нет dislikes или их вектор нулевой → dislike_similarity=0.
- Нет выбранного формата → format_match=0.
- Нет/неверно число записей на материал (включая NaN/Infinity/отрицательные)
  → popularity=0. Ненулевые счётчики: log(1+n)/max(log(1+n)); все нули/пустой
  каталог → нули. Отсутствие счётчика не выводится из отсутствия истории гостя.
- Нет положительной истории → используется вектор текущего запроса. Если нет
  и запроса — общий стартовый текст. Если encoder вернул нулевой вектор, пробуем
  центроид доступных материалов выбранных меток, стартовый текст, затем средний
  вектор доступного каталога; пустой/нулевой каталог
  оставляет нулевой вектор и конечные оценки. Запрос не заменяется историей по умолчанию.

## Диагностика и журнал

Существующие score, cosine и factors.topic/format/popularity сохраняются. В factors
добавляются cosine, dislike, continuation в [0, 1]. Новый score_breakdown содержит
версию формулы, используемые веса, подписанные contributions, base_score,
diversity_penalties и selection_score на момент выбора карточки. Округление может
дать расхождение суммы на уровне последних десятичных знаков.

Мягкое разнообразие hybrid остаётся отдельным этапом: штраф 0.05 за положительную
близость к уже выбранному и 0.01 за каждую ранее выбранную карточку такого формата.
Отрицательная близость не создаёт бонуса. Число повторов формата — счётчик, а не
нормализованный признак основной формулы. Бейзлайны topic/cosine не получают MMR.

CLI и сервер принимают --ranking-log. Для каждой возвращённой карточки в stderr
идёт JSON с algorithm, rank, factors и score_breakdown, без task, названий, URL,
ID карточек/профилей, истории или ответов. query_vector_source в ответе указывает,
использован запрос, история, default, topic_centroid, catalog_centroid или zero.
По умолчанию журнал выключен, диагностика
в API доступна всегда. Журнал не записывается в PostgreSQL и не растит гостевой профиль.

## Критерии приёмки

Границы отрицательных/нулевых/единичных косинусов, корректные диапазоны и fallback
проверяются тестами. Проверяются ослабленный штраф и вклад популярности, сумма
вкладов/штрафов, отсутствие текстов/ID в журнале, неизменность cosine/topic-бейзлайнов,
HTTP и поиск вместе с новым движком. На настоящем индексе выполняется read-only smoke
без LLM. Новые веса — ручная настройка по поручению, не результат оптимизации на
evaluation/profiles.json и не доказательство улучшения качества/конверсии.
