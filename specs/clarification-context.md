# Тематические уточнения

Вопрос сохраняет тему текущего запроса. Пример: «искуственный интеллект» должен
дать уточнение об использовании ИИ, а не общий опрос о бизнес-задаче.

Общий локальный AI_PATTERN распознаёт ИИ/AI/нейросети и распространённые пропуски
согласных в «искусственный интеллект». Он используется для бизнес-признака,
точного фокуса и проверки вопроса; исходные строки наружу не отправляются.

В LLM-payload добавляются request_focus (константный фокус, ИИ приоритетнее общей
автоматизации) и profile_topics (до трёх константных обобщённых бизнес-тем истории).
Профиль лишь помогает предложить варианты, не заменяет текущую задачу и не требует
от пользователя остаться в старой сфере. Строки названий, история действий, ID,
числа весов, персональные данные не отправляются. Слова в неизвестных метках не
копируются: они только выбирают константы из FEATURES.

Валидатор требует упоминания распознанного фокуса в title. Для ИИ подходят ИИ,
искусственный интеллект, нейросети; generic title без темы не показывается даже
при тематических вариантах. На topic_mismatch — одна попытка исправления с тем же
безопасным payload и константным validation_feedback, без текста отвергнутого ответа.
Повторный mismatch → вопрос отсутствует, локальная выдача сохранена. Это ограниченный
лексический контроль, не универсальная проверка смысла. Готовых вопросов/ответов нет.

Прочие ошибки API/JSON/ПДн не повторяются; уже отвеченный параметр и лимит двух
вопросов сохраняются. needs_clarification=false/question=null принимается: фокус
не обязывает задавать вопрос. До двух вызовов по 900 выходных токенов/30 с на один
шаг, вторая попытка только для восстановления потерянной темы. Без ключа — без вопросов.

Контракт /search, schema результата модели, БД и индекс не меняются. Пересборка
эмбеддингов не нужна. Проверки: опечатки, профиль marketing/finance/new, контроль
payload, generic/другая тема/повторный отказ, правильный вопрос и следующие ответы,
неизменность ранжирования и полный HTTP/PG сценарий без внешней LLM.
