# Облачная проверка рекомендаций

Задача: жюри подключает API-ключ без установки локальной LLM. Основной вариант —
OpenRouter Chat Completions; другой совместимый endpoint задаётся конфигурацией.
Математика и эмбеддинги остаются локальными. Порядок и состав выдачи не меняются.

Дополнение: в умном режиме поиска LLM также решает необходимость уточнения и
формулирует вопрос и варианты (`reco/clarification.py`, specs/dynamic-clarifications.md).
При достаточном локальном контексте уточнение не вызывается (not_needed).
Используется общий structured_call с теми же HTTPS/NoRedirect/тайм-аутами и
политикой OpenRouter. До 900 выходных токенов для вопроса с вариантами; исходный
запрос, каталог и история поведения не передаются. Помимо фиксированных признаков
в следующий вызов входят лишь фиксированные бизнес-признаки прежних пар вопрос/ответ,
без самих строк/исходных чисел. Клиентский текст не может подменить выбор:
используются подписанные токены, связанные с запросом. Полный выбранный ответ
используется только в локальном ранжировании.
Уточнения также получают константный request_focus и до трёх обобщённых тем профиля
profile_topics. Заголовок обязан сохранять тему. Если она потеряна, допускается один
повтор генерации с константной validation_feedback без отвергнутого текста;
повторный topic_mismatch сохраняет выдачу без вопроса. Веса/ID/история профиля
по-прежнему не передаются. См. specs/clarification-context.md.
Обычный режим поиска не вызывает ни уточнение, ни проверку карточек.

## Контракт и конфигурация

Сохраняется verify(task, items) → (проверки по исходным ID, статус).
LLM_PROVIDER: openrouter (по умолчанию), compatible, ollama или disabled.
LLM_API_KEY и LLM_MODEL обязательны для облака; LLM_BASE_URL для compatible
обязателен, для OpenRouter фиксирован https://openrouter.ai/api/v1.
Старые OLLAMA_URL/OLLAMA_MODEL поддерживаются при отсутствии явного выбора
провайдера и нового API-ключа. Проверка карточек вызывается по --llm / use_llm=true;
LLM-уточнение — автоматически в search_mode=smart при непустом запросе, если
вопросы не пропущены и лимит не исчерпан.

HTTPS, Bearer authentication, POST /chat/completions, JSON schema ответа.
Не более 5 кандидатов и 1200 выходных токенов; timeout 30 с, без повторов и
переадресаций. OpenRouter: data_collection=deny, zdr=true, require_parameters=true.
Если подходящего маршрута нет, политика не ослабляется, остаётся обычная выдача.
Совместимый другой сервис требует собственной проверки его политики хранения.

## Минимизация данных

В облако НЕ отправляются исходный task, UserId/anon_id, история, UUID карточек,
названия, аннотации, ссылки, тексты и векторы. Вместо свободного текста передаются
только фиксированные бизнес-темы/действия из локального словаря признаков.
Это позволяет исключить имена, контакты и произвольные идентификаторы по
конструкции, без обещания универсального распознавания персональных данных regex.
Неизвестный контекст не отправляется. Цена этой политики — облако проверяет
широкое соответствие признаков, а не все нюансы исходного запроса.

Карточка должна иметь созданный при индексации llm_public_metadata=true:
опубликована, доступна; статьи/курсы/подкасты имеют известный тип доступа
Public/Paid/Subscription. IsPublic не подтверждает право доступа (Q&A-2). Для остальных
поддерживаемых типов используются только публичные метаданные витрины.
Полные тексты/описания не входят в облачный summary. Старый индекс без флага
не считается разрешением передачи: нужна переиндексация. Внешние карточки
с непроверенным происхождением отбрасываются. Неизвестные категории/форматы
не попадают в payload. Псевдонимы c1…c5 сопоставляются с UUID только локально.

Ответ содержит релевантность и точную цитату из отправленного контролируемого
summary, не из закрытого материала. Проверяются форма, ID, дубли и цитата.
Статусы ошибок не включают тело ответа сервиса, ключ или пользовательский текст.
Без ключа/модели, при отказе политики, ошибке HTTP/JSON/тайм-ауте выдача сохраняется.

## Проверки и критерии готовности

Тесты перехватывают реальный сериализованный request: только разрешённые поля,
отсутствие ПДн/закрытого текста/UUID, локальные псевдонимы, строгая schema и
настройки маршрутизации. Проверяются fallback, 401/429/тайм-аут, отказ redirect,
неизвестные ID/цитаты/дубли и сохранение профиля/порядка рекомендаций.
Платный живой вызов без предоставленного ключа не выполняется и не заявляется
проверенным. Ключ хранится только в окружении/.env, не в коде или браузере.
Схема PostgreSQL не меняется. Добавление поля индекса меняет fingerprint, старые
профили между индексами не переносятся; предыдущие поколения остаются для отката.
