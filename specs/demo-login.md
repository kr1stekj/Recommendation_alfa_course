# Демо-вход для проверки синтетических пользователей

Владелец выбрал вход выбором готового профиля; регистрация не требуется.
Это общедоступные тестовые роли, не проверка личности/паролей реальных клиентов.
Обычный поиск/гостевой режим продолжают работать. Внешние LLM при проверках не вызываются.

## Поведение

Кнопка «Войти» открывает список: новый пользователь без истории, запуск бизнеса,
маркетинг, налоги/маркетплейсы, управление командой, финансы. Интересы задаются
синтетическими просмотрами/завершением до трёх доступных материалов, найденных
по меткам текущего каталога. Разметка evaluation/profiles.json не используется
как история: она остаётся отдельной проверочной выборкой.

Каждый вход создаёт отдельную копию профиля и opaque серверную сессию. У разных
браузеров и разных входов история изолирована. Обновление страницы восстанавливает
тот же вход по HttpOnly cookie; профиль/токен не сохраняются в localStorage.
«Сбросить демопрофиль» восстанавливает исходные синтетические события. Выход
отзывает сессию, удаляет её агрегат и возвращает прежнего гостя браузера.
Гостевые события не переносятся автоматически в синтетический профиль.

Рекомендации учитывают тестовые интересы только в умном режиме. Вход и восстановление
демовхода включают умный режим; его можно выключить вручную. Смена профиля очищает
текст запроса/дополнительный контекст/цепочку уточнений и закрывает карточку.
На странице явно видны выбранная роль, синтетическая природа и число стартовых
действий. Если у роли нет совпадающих доступных материалов, показывается отсутствие
стартовой истории; недоступные/выдуманные материалы не добавляются.

## Контракт

- GET /demo/accounts — публичные описания ролей и число доступных стартовых событий.
- GET /demo/session — authenticated, account|null, profile_id|null, synthetic=true;
  просроченный/неизвестный cookie даёт гостевой статус и удаляется.
- POST /demo/login {account_id} — новая сессия и профиль, прежняя сессия отзывается.
- POST /demo/logout {} — идемпотентный выход, очистка cookie/своего демопрофиля.
- POST /demo/reset {} — требует сессии, возвращает стартовую тестовую историю.

Cookie: случайные 32 байта, HttpOnly, SameSite=Strict, Path=/, Max-Age=3600.
На локальном HTTP Secure не ставится. Сессия в памяти, абсолютный TTL 1 час,
максимум 512 сессий на процесс; при достижении лимита новый вход → 429.
Перезапуск отзывает вход. Это один процесс локального прототипа, не production SSO.
POST сохраняет JSON/Origin-защиту. Подмена profile_id при активной сессии → 403;
демо-ID без своей сессии → 401, до обращения к рекомендателю/событиям/удалению.
Просроченный cookie в запросе действий → 401, чтобы действие не попало гостю.
Слияние гостя и демопрофиля запрещено. Старые несинтетические CLI/API-контракты
сохраняются; демо-вход не добавляет авторизацию исходным user:UUID из backup.

## Хранение и совместимость

Демо-ID anon:demo_<случайный токен> в пространстве текущего fingerprint, payload
в существующей reco.profiles с anonymous TTL/лимитами. Они являются отдельными
тестовыми состояниями, несмотря на UI-вход в роль. Seed/клики не записываются в
исходные public/reco.history и не используют реальные пользовательские ID.
Выход/истечение сессии удаляют агрегат; после рестарта оставшиеся состояния
очищаются существующим гостевым TTL (24 часа idle, максимум 7 дней).
Новых таблиц, паролей, миграций и пересборки embeddings нет. При откате cookie
утрачивает действие, тестовые строки удаляются обычным TTL.

## Проверки

Unit и настоящий HTTP/PostgreSQL: гостевой режим, доступные роли, вход/выход/сброс,
перезагрузка, разные cookie jar, подмена ID/сессии, expiry/лимит/рестарт, CSRF,
изоляция исходной истории и гостей, fallback пустого каталога/нет тем. UI проверяется
на широком/узком экране без реальных LLM-вызовов; регистрационного интерфейса нет.
