# Приоритет текущего запроса в умном поиске

Ошибка: история меняла направление поискового вектора и при отсутствии точной
связи бизнес-признака с темой каталога давала дополнительный тематический бонус.
«ИИ» распознавался как «Автоматизация», а каталог содержит «ИИ и автоматизация».

Умный поиск с непустой задачей использует query_first=true: кандидаты отбираются
по вектору текущего запроса до смешивания истории. Бонус темы берётся только из
текущей задачи, а не из прежних интересов. История получает 10% при последующем
смешивании векторов и может менять порядок внутри пула. Размер пула — max(20,3*k),
порог близости прежний (TF-IDF: 40% от лучшего, semantic: лучший минус 0.2).
Если среди доступных материалов выбранного формата есть совпадение с текущими
темами, пул ограничивается этими материалами. Остаток до k не заполняется другими
темами. Если совпадающих меток нет, остаётся семантический отбор. Исторические
темы не могут расширить пул.
Нулевая векторизация запроса получает локальный fallback до добавления истории.
Пустая задача сохраняет прежнюю персонализацию. /recommend по умолчанию не меняется.

Запросы про ИИ связываются с существующими метками «ИИ и автоматизация» и
«Автоматизация». Существующий признак «Автоматизация» с CRM также сохраняется.

Один явно указанный формат в запросе (статья/курс/документ/подкаст) задаёт фильтр.
Смешанный запрос на несколько форматов и отрицания не трактуются как строгий выбор.
Явный ответ на уточнение формата или legacy answers.format имеет приоритет.
Если такого формата нет в каталоге, выдача пустая; другой формат не подставляется.
required_format — необязательная строка формата в /recommend; query_first — bool,
по умолчанию false. Обычный поиск по словам и контракт /search не меняются.

Проверки: запросы про ИИ на всех деморолях и госте; старые интересы не подставляются
в темы нового запроса; формат, пустой поиск, завершённые/dislike, неизвестный запрос,
ошибки параметров, HTTP и неизменность профиля. Реальные LLM при проверках не нужны.
Схема БД, каталог и веса модели не меняются; эмбеддинги пересчитывать не требуется.
