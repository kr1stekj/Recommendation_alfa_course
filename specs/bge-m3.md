# Замена encoder на BGE-M3

Поручение: заменить ruBERT одной из предложенных открытых моделей. Выбрана
официальная BAAI/bge-m3, MIT, revision 5617a9f61b028005a4858fdac845db406aefb181.
Источник: https://huggingface.co/BAAI/bge-m3 и 1_Pooling/config.json этой revision.
Публичные цифры скорости не переносятся на Mac без измерения.

## Поведение и входы

Семантический encoder по умолчанию — BGE-M3, CLS pooling, L2 normalization,
1024 координаты. Нейросеть работает локально. Облачная LLM остаётся отдельной
частью умного поиска, обычный поиск остаётся TF-IDF. Sparse/ColBERT BGE не включаются.

На CPU с 8 ГБ RAM: max_length=512, batch_size=4. Нативный предел BGE — 8192;
больший контекст задаётся явно и требует отдельной проверки ресурсов. Параметры
сохраняются в encoder.json, каталог и будущие запросы используют одинаковую модель,
revision, pooling и max_length. Старая rubert-tiny2 (312 координат) поддерживается
как явный вариант для сравнения/старого индекса, TF-IDF тоже сохраняется.
Неизвестные модели не принимаются без корректного адаптера.

Устройство исполнения CPU по умолчанию. Для разовой сборки на Apple Silicon
доступно --device mps; для runtime — EMBEDDING_DEVICE=mps. Устройство записывается
в audit/benchmark, не фиксируется как семантическая часть encoder.json: индекс
можно переносить на CPU. Недоступный MPS даёт явную ошибку. CPU-сравнение выполняется
с --device cpu у обеих моделей; отдельно проверяется близость CPU/MPS-векторов.

Проверка организаторами — Windows через Docker Desktop с Linux containers/WSL 2,
EMBEDDING_DEVICE=cpu по умолчанию. Модель и код не требуют macOS. В Compose кеш
и поколения находятся в named volumes reco_models/reco_artifacts (Linux FS),
а не в NTFS-bind mount. Старые host-папки сохраняются; переход Compose означает
разовую индексацию в новых томах. Public-схема и том PostgreSQL не меняются.
PowerShell-инструкция находится в README. Реальный Windows/Docker запуск в этой
среде недоступен и не заявляется проверенным.

CLI reco.build: --model, --max-length, --batch-size. Compose/start.py получают
EMBEDDING_MODEL, EMBEDDING_MAX_LENGTH, EMBEDDING_BATCH_SIZE. Существующий индекс
другой модели/длины не переиспользуется молча: старт прекращается с инструкцией
пересобрать индекс либо выбрать прежнюю конфигурацию. Это не автоматическое
обучение, не обновление чужой БД и не загрузка каталога в облако.

У официальной revision BGE веса pytorch_model.bin. Используется PyTorch 2.6+
weights_only=true, trust_remote_code=false и low_cpu_mem_usage=true с accelerate;
не выполняется произвольный pickle/remote code. ruBERT использует safetensors.
Кеш вне Git, загруженные веса имеют закреплённое происхождение/версию; контрольная
сумма сверяется с LFS SHA256. Неофициальные Docker-образы не используются.

## Миграция и откат

Пересобрать новое поколение из исходного backup. До публикации BGE-индекса
сохранить ссылку на старое поколение ruBERT для сравнения и отката. Векторы 312/1024
не смешиваются. fingerprint меняется; история импортируется для нового dataset,
профили между fingerprint не переносятся. Исходные public-таблицы не меняются.
Предыдущие поколения и веса не удаляются. Сервер после сборки перезапускается.

## Критерии приёмки

- Конфигурация encoder воспроизводится после save/load, параметры валидируются;
  сохраняется работоспособность TF-IDF и старого ruBERT-индекса.
- Настоящие BGE-веса загружаются, получается матрица N×1024 без NaN/Infinity,
  ненулевые векторы нормированы; следующий запуск работает из кеша офлайн.
- Индекс пересобран из настоящего backup, проверены manifest/fingerprint/история,
  новый движок используется живым API. Обычный/умный режимы сохранены.
- Сопоставимое сравнение ruBERT и BGE на тех же исходных карточках и пяти прежних
  seed-профилях; результаты помечены повторным измерением на неполной разметке.
  Отдельно измерены warm query latency, размер/время индексации и условия CPU/RAM.
- Нет неподтверждённого обещания качества, скорости или промышленной готовности.
