# Проверка первого трека — 15.11.2026

Проверяется ветка `feat/cloud-llm-api`, база `main@2a02e8e`, включая
облачную интеграцию и «Умный поиск». Это не состояние опубликованного
main. Основания: PDF кейса, скриншоты критериев, оба Q&A организаторов и запрос
владельца. Последующее уточнение владельца — заменить ruBERT одной из предложенных
моделей; выбрана BGE-M3, контракт миграции — specs/bge-m3.md.

**Вывод:** пользовательский сценарий первого трека реализован локально. Нельзя
заявлять полную готовность конкурсной сдачи, доказанный рост конверсии или превосходство
модели: остаются презентация, проверка Docker/Windows и усиление оценки.

Сопоставимый прогон 15 ноября на прежних 5 seed-профилях, до изменения hybrid-v2:

| Метод | Precision@5 | NDCG@5 |
|---|---:|---:|
| Темы + популярность при равенстве | 0.12 | 0.0810 |
| ruBERT / косинус | 0.24 | 0.3668 |
| ruBERT / гибрид | 0.36 | 0.4651 |
| BGE-M3 / косинус | 0.36 | 0.5789 |
| BGE-M3 / гибрид | 0.44 | 0.5458 |

Качество новых весов hybrid-v2 не измерялось. Нормализация, fallback и числовая
диагностика проверяются отдельно; эти метрики не доказывают улучшение новой формулы.

Условия: локальный CPU, один каталог/история из backup от 15.11.2026, LLM выключена,
одинаковые профили, `scripts/benchmark_embeddings.py`. Это повторная проверка на
известной неполной разметке, не независимый контроль и не оценка диалогового интерфейса.
Полные локальные результаты: `artifacts-rubert/benchmark.json` и
`artifacts/benchmark-bge.json` (в Git не добавляются). Методика, задержки и ограничения
описаны в [сравнении encoder](embedding-comparison.md). Windows/Docker run не проверен:
Compose настроен на CPU, модели и индекс — в Linux named volumes; PowerShell-инструкция
есть в README. Нативная CPU-проверка на Mac не заменяет запуск на Windows.

## Существенные уточнения Q&A-2

- ContentAccess: 0 — пробная запись, 1 — покупка, 2 — групповой доступ, 10 — отозван.
  Исправлен признак owned: только 1/2, а не любая запись. Он не является purchase-событием.
- Покупка в A/B — курс или подписка. Цена подписки не цена каждой статьи.
- Courses.Cost=NULL означает бесплатный курс, но доступ проверяется отдельно.
  Интерфейс не объявляет любой материал с пустой ценой бесплатным.
- TypeId определяет доступ статьи; IsPublic — редакторский флаг. Известный Public
  UUID подтверждён справочником CourseTypes в backup. Неизвестный тип не разрешает тело.
- RecommendedItems — ручные редакторские связи без показов/кликов; не ground truth.
- Стандартизированного уровня сложности/prerequisites нет. Target, длительность
  и число уроков показываем только при наличии, не генерируем как факты.
- Данные реального происхождения, обезличены. Тестовые профили помечены синтетическими.
- Текст страницы документа в backup есть; содержимое файла вложения не разобрано.
  Текущий MVP использует карточку документа, не утверждает поиск внутри docx/pdf.
- ImageUrl разрешён, но иллюстрации не обязательны: интерфейс не загружает внешние
  картинки и не отправляет посетителя на CDN при каждом показе карточки.

## Как проверить эффект после внедрения

1. Зафиксировать варианты: контроль — текущий поиск/тематическая подборка;
   эксперимент — умный поиск с уточнением. Стабильное случайное распределение
   по псевдонимному пользователю, отдельный анализ новых и возвращающихся.
2. До старта выбрать окно атрибуции (например, 14 дней), минимально значимый эффект,
   уровень значимости и размер выборки по исходной конверсии. Пять тестовых профилей
   для этого не подходят. Не менять веса на итоговой контрольной выборке.
3. На платформе добавить показы с request_id/variant/item_id, клики, начало обучения,
   регистрацию и серверно подтверждённую покупку курса/подписки. События покупки
   дедуплицировать по транзакции; не получать их из клиентской кнопки.
4. Основная метрика — доля пользователей с покупкой; дополнительные — регистрация,
   начало обучения, CTR, активные дни и возврат. Защитные — время ответа, отказы,
   ошибки и доля запросов без подходящей выдачи. Активный день: хотя бы одна страница.
5. Считать эффект и доверительный интервал по пользователю. Дождаться выбранного
   окна и объёма; не останавливать тест при первом положительном значении.
   Сырые гостевые события очищать по согласованному TTL, агрегаты эксперимента
   сохранять без контактов и полных поисковых строк.

## Модели из предложенного списка

Encoder по умолчанию заменён на локальный BGE-M3; генеративная LLM подключается отдельно.
Ни BGE/Qwen reranker, ни Qdrant/Milvus сейчас не установлены. Для 1126 векторов
точный матричный косинус покрывает весь каталог; отдельная векторная БД пока не нужна.

По официальным карточкам: [BGE-M3](https://huggingface.co/BAAI/bge-m3) поддерживает
dense/sparse/multivector и контекст 8192; текущий движок использует только dense.
[Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) требует
своего способа pooling и инструкций для запросов, а также совместимой версии transformers.
[E5-large-instruct](https://huggingface.co/intfloat/multilingual-e5-large-instruct)
использует average pooling и инструкции у запросов.
[BGE-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) — отдельная
попарная модель, не замена косинуса одним флагом.

Реализован адаптер BGE-M3: CLS pooling по официальной конфигурации, L2 normalization,
1024 координаты, закреплённая revision и ограничение по умолчанию 512 токенов/batch 4.
Старый ruBERT поддержан для старого индекса/сравнения. E5/Giga/Qwen требуют своих
адаптеров и здесь не установлены. Индексы 312/1024 не смешиваются; старое поколение
сохраняется. При старте несовпадение выбранной модели или max_length отклоняется.
Для большой модели добавлен accelerate; официальный checkpoint загружается только
с weights_only=true. Сторонние Docker-образы со скриншота не используются.

Измерения воспроизводятся через scripts/benchmark_embeddings.py: те же профили,
проверка хэша исходных карточек/истории, NDCG/Precision, warm p50/p95, RSS и условия
CPU/RAM. Утверждение «самая точная/быстрая» для нашего каталога пока не доказано.
