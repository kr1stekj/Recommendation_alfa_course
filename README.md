# Альфа-Курс · прототип

Полный порядок запуска приложения. Основной вариант — Docker: он поднимает
PostgreSQL и Python-сервер сам. Для Windows используй этот вариант; локальный
Python на macOS/Linux описан ниже.

Техническая документация: [архитектура, алгоритмы, API, получение ключа и проверка](docs/TECHNICAL_GUIDE.md).

## 1. Что понадобится

- Git и Docker с командой `docker compose`. На Windows — запущенный Docker Desktop
  в режиме Linux containers / WSL 2.
- Исходный `alfa_course_hackathon.backup` от организаторов. Его нет в репозитории.
- Интернет для первой сборки и скачивания весов BGE — около 2,3 ГБ.
- Ключ OpenRouter для уточняющих вопросов LLM. Без него локальные рекомендации
  работают, но LLM-вопросов не будет. Ollama не нужна.

Готовые эмбеддинги уже в репозитории, около 4,5 МиБ: **считать каталог заново не нужно**.
Веса нужны отдельно, чтобы кодировать новые поисковые запросы.

В умном поиске текущая задача определяет кандидатов и темы. При непустом запросе
вектор смешивается как 90% запроса + 10% истории; прежние интересы уточняют порядок,
но не подставляются вместо темы запроса. «ИИ», «AI» и «нейросети» связаны с темой
«ИИ и автоматизация». Один явно названный формат («статьи про ИИ») ограничивает
выдачу этим форматом. Если есть материалы текущей темы, подборка не дополняется
чужими темами ради количества. Без запроса сохраняются рекомендации по истории.
Пересборка эмбеддингов не нужна. Контракт: [specs/search-intent-priority.md](specs/search-intent-priority.md).
Уточняющий вопрос сохраняет тему запроса, в том числе при распространённых опечатках
в «искусственный интеллект». LLM получает только безопасный фокус и обобщённые
темы профиля. Общий вопрос без темы отправляется на одну попытку исправления;
если исправление не удалось, остаётся локальная подборка без такого вопроса.
Тексты вопросов и вариантов генерируются моделью. Контракт: [specs/clarification-context.md](specs/clarification-context.md).

## 2. Получить проект и положить дамп

Для новой копии:

```bash
git clone https://github.com/Stanbongo/alfa_hackathon.git
cd alfa_hackathon
```

Если проект уже скачан, открой терминал в его корне — там, где лежит `compose.yaml`.
Все дальнейшие команды выполняются из этой папки.

### Windows · PowerShell

Замени путь в `Copy-Item` на расположение своего дампа:

```powershell
New-Item -ItemType Directory -Force data | Out-Null
Copy-Item "C:\путь\к\alfa_course_hackathon.backup" "data\alfa_course_hackathon.backup"
if (-not (Test-Path .env)) { Copy-Item env.example .env }
```

### macOS / Linux · bash или zsh

```bash
mkdir -p data
cp "/путь/к/alfa_course_hackathon.backup" data/alfa_course_hackathon.backup
test -f .env || cp env.example .env
```

Существующий `.env` эти команды сохраняют.

## 3. Настроить LLM и проверить `.env`

Полная инструкция получения ключа OpenRouter и настройки прокси:
[подключение внешних сервисов](docs/TECHNICAL_GUIDE.md#openrouter-получение-и-подключение-ключа).

Открой `.env` в редакторе и вставь собственный ключ:

```dotenv
LLM_PROVIDER=openrouter
LLM_API_KEY=ВАШ_КЛЮЧ_OPENROUTER
LLM_MODEL=openai/gpt-4.1-mini
```

Для работы по ключу у провайдера должны быть доступны выбранная модель и лимит.
Если пока запускаешь без LLM, оставь `LLM_API_KEY=` пустым. Ключ хранится локально
на сервере; `.env` исключён из Git.

Пошаговая [инструкция подключения и проверки прокси](docs/proxy-setup.md).

Для работы с openrouter нужен прокси, добавь в тот же `.env`:

```dotenv
RECO_PROXY_URL='http://USER:PASSWORD@HOST:PORT'
```

Замени реквизиты своими. Пустое `RECO_PROXY_URL=` отключает прокси.
Настройка действует только в контейнере приложения; PostgreSQL и локальные
адреса обходят прокси. После изменения `.env` пересоздай сервис:

```bash
docker compose up -d --force-recreate recommender
```

Ключ, реквизиты прокси и архив с ними не добавляй в Git. `.env`, папки
`private/` и `output/` исключены из репозитория и Docker build context.
Презентация без секретов находится в `docs/presentation/`.

Для Docker сохрани настройки готового индекса:

```dotenv
EMBEDDING_BACKEND=semantic
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_MAX_LENGTH=512
EMBEDDING_DEVICE=cpu
USE_PRECOMPUTED_EMBEDDINGS=1
```

В шаблоне они уже указаны. Для стандартной БД Docker строка `DATABASE_URL` в `.env`
должна оставаться закомментированной: Compose сам задаёт адрес `postgres:5432`.
Адрес `localhost:5433` используется только Python-сервером на хосте.

## 4. Запустить приложение

```bash
docker compose up --build
```

При первом запуске устанавливаются зависимости, из `.backup` восстанавливаются
каталог и история, подготавливается кеш весов. Повторная векторизация не выполняется.
Дождись сообщения `Local demo API`, затем открой:

**http://127.0.0.1:8000/**

В случае возникновения ошибки:

```
docker compose up -d --force-recreate recommender
```

Пока сервер готовится, страница может не открываться. Прогресс виден в текущем
терминале; из другого терминала логи доступны командой:

```bash
docker compose logs -f recommender
```

Проверка готовности в PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

В bash/zsh:

```bash
curl http://127.0.0.1:8000/health
```

Ожидаются `status: ok`, `embedding_model: BAAI/bge-m3`, `vector_dimension: 1024`
и `embedding_device: cpu`. Это проверка API; доступность ключа LLM проверяется
при поиске, который действительно требует уточнения.

## 5. Проверить поиск и демопользователей

При открытии страницы и пустой строке показывается персональная подборка, даже
с выключенным «Умным поиском». Обычно это 10 карточек: 8 по истории интересов,
1 популярная и 1 из другой темы. Персональная часть чередует до четырёх тем,
чтобы небольшое преимущество кликов по ИИ не вытесняло налоги, и наоборот.
Дополнительные карточки подписаны «Популярное» / «Для знакомства»; повторов нет.
Карточки показывают все темы каталога: например, «Налоги и законы» вместе
с «Управление командой». Порядок этих меток не задаёт главную тему.
Последние положительные действия сильнее старых: их вес уменьшается вдвое
за сутки. В ленте больше мест получают недавно открывавшиеся темы; другие
интересы тоже представлены. Повторный клик освежает интерес, повторная доставка
того же события - нет. Поиск сам по себе не сохраняет предпочтения.
Если истории ещё нет, показывается стартовая подборка. LLM для неё не вызывается.
При перезагрузке сохраняется ID гостя и учитываются его прежние клики.
После ввода текста обычный режим по-прежнему ищет по словам, умный — по смыслу.

1. Введи запрос и нажми «Найти». С выключенным переключателем работает обычный поиск.
2. Включи «Умный поиск». При недостаточном контексте LLM может задать вопрос
   у строки поиска; для конкретной задачи вопрос может не понадобиться.
3. Для проверки синтетических пользователей нажми «Войти» и выбери готовый профиль.
   Регистрация и пароль не нужны.
4. Открывай карточки и используй «Полезно», «Уже изучил», «Не подходит», чтобы
   проверить изменение рекомендаций. «Выйти» возвращает гостевой режим.

Без рабочего ключа LLM умный режим покажет локальную подборку и сообщение
о недоступности уточнений.

## 6. Остановка, повторный запуск и обновление

Остановить: `Ctrl+C`, затем:

```bash
docker compose down
```

Повторно запустить:

```bash
docker compose up --build
```

БД, индекс и веса сохраняются в Docker-томах; заново скачивать веса и считать
каталог при обычном перезапуске не нужно.

После изменения ключа в `.env` пересоздай сервис:

```bash
docker compose up -d --build recommender
```

Для обновления чистой копии репозитория: `git pull --ff-only`, затем
`docker compose up --build`. При наличии собственного кода сначала сохрани изменения.

## 7. Локальный Python на macOS / Linux

Это альтернативный запуск. Нужны Python 3.9–3.11, PostgreSQL 17 и `pg_restore`
версии 17+ в `PATH`. Подготовь дамп и `.env` по пунктам 2–3. Если установлен
PostgreSQL через Homebrew, добавь каталог его `bin` в `PATH`.

Можно поднять только БД в Docker:

```bash
docker compose up -d postgres
docker compose exec postgres pg_isready -U reco -d reco
```

Дождись `accepting connections`. Для собственной PostgreSQL заранее создай БД
и пользователя с правом создавать служебную схему/таблицы.

Первый запуск из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pg_restore --version

# Загрузи свой локальный .env; Python сам его не читает.
set -a
source .env
set +a
# Для БД из Compose; для своей БД замени URL, при ином пароле замени и его.
export DATABASE_URL='postgresql://reco:local-demo-only@127.0.0.1:5433/reco'

python -m reco.precomputed restore --backup data/alfa_course_hackathon.backup
python -m reco.model_cache
python -m reco.server
```

Открой тот же адрес **http://127.0.0.1:8000/**. Остановка сервера — `Ctrl+C`.
При следующих запусках активируй `.venv`, загрузи `.env`, снова задай `DATABASE_URL`
и выполни только `python -m reco.server`. Restore и скачивание кеша повторять не нужно.
Если индекс остался, а БД новая, импортируй историю:

```bash
python -m reco.migrate --backup data/alfa_course_hackathon.backup
```

## 8. Если не запускается

| Проблема | Что сделать |
|---|---|
| Docker daemon недоступен | Запусти Docker Desktop / Engine и проверь `docker compose version`. |
| Не найден `.backup` | Проверь точный путь `data/alfa_course_hackathon.backup` и имя файла. |
| `Backup SHA256 differs` | Для готовых векторов нужен тот же исходный дамп организаторов. Для другого дампа требуется явная пересборка — [инструкция](REFERENCE.md#готовые-эмбеддинги-для-команды). |
| `model/max_length` или `different backend` | Верни настройки из пункта 3. Для старого Docker-индекса используй восстановление ниже. |
| Контейнер не подключается к БД | Убери `DATABASE_URL` из `.env` и окружения терминала, чтобы Compose использовал `postgres:5432`. В bash/zsh: `unset DATABASE_URL`; в PowerShell: `Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue`. |
| Модель не скачалась / кеш неполный | Проверь сеть и свободное место, повтори запуск. Для локального Python выполни `python -m reco.model_cache`. |
| Не появляются вопросы LLM | Проверь ключ, модель и лимит OpenRouter, пересоздай сервис после изменения `.env`, включи «Умный поиск». Конкретный запрос может не требовать вопроса. |
| Порт 8000 занят | Останови свой прежний сервер. Для локального Python можно выбрать `python -m reco.server --port 8001`. |
| `pg_restore` не найден | Для локального Python установи клиент PostgreSQL 17+ и добавь его `bin` в `PATH`. В Docker он уже включён. |

Если в Docker-томе остался старый или повреждённый индекс, восстанови готовый
с сохранением БД и прежних поколений:

```bash
docker compose stop recommender
docker compose build recommender
docker compose run --rm recommender python -m reco.precomputed restore --backup /data/alfa_course_hackathon.backup
docker compose up -d recommender
```

Восстановление требует исходного дампа.

Архитектура, алгоритмы и дополнительные настройки: [REFERENCE.md](REFERENCE.md).
